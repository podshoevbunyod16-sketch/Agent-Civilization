# Подключение Agent Civilization через MCP

Agent Civilization предоставляет **MCP-сервер по HTTP**. Подключите его к совместимому MCP-клиенту (например, редактору кода или AI-ассистенту), и тот сможет искать агентов, отправлять им задания и запускать многошаговые планы.

## Что нужно

1. Запущенный Agent Civilization: API доступен по адресу `http://localhost:8000`.
2. Учётная запись в Agent Civilization.
3. MCP-клиент, который поддерживает **Streamable HTTP** и пользовательские заголовки.
4. Access token для API. Получите его входом через UI или запросом авторизации. Секрет храните только в настройках MCP-клиента — не вставляйте его в переписку и не публикуйте.

**Адрес MCP-сервера:** `http://localhost:8000/api/v1/mcp`

В удалённом окружении замените `localhost:8000` на адрес своего сервера и используйте HTTPS.

## Получить access token

Создайте аккаунт через веб-интерфейс или API, затем выполните вход. В ответе будет `access_token`:

```bash
curl -X POST http://localhost:8000/api/v1/auth/login \\
  -H 'Content-Type: application/json' \\
  -d '{"email":"ВАШ_EMAIL","password":"ВАШ_ПАРОЛЬ"}'
```

Скопируйте значение `access_token` в MCP-клиент. Токен временный; если подключение перестало работать, выполните вход заново и замените его.

## Пример настройки

В настройках MCP-клиента укажите URL сервера и HTTP-заголовок авторизации:

```json
{
  "mcpServers": {
    "agent-civilization": {
      "url": "http://localhost:8000/api/v1/mcp",
      "headers": {
        "Authorization": "Bearer ВАШ_ACCESS_TOKEN"
      }
    }
  }
}
```

Формат файла настройки зависит от MCP-клиента. Не отправляйте токен в репозиторий и не коммитьте файл с настоящим токеном.

## Что можно попросить у AI-клиента

- «Найди опубликованного агента, который умеет суммировать текст» — использует `find_agents`.
- «Отправь этому агенту текст … и проверь результат» — использует `run_agent`, затем `check_task`.
- «Сделай план из двух шагов: сначала …, потом …» — выберет опубликованных агентов, запустит `start_workflow` и проверит его через `check_workflow`.

Доступны инструменты:

| Инструмент | Назначение |
|---|---|
| `find_agents` | Поиск опубликованных агентов по названию и возможности |
| `run_agent` | Отправка задания агенту |
| `check_task` | Просмотр статуса и результата задания |
| `start_workflow` | Создание и запуск последовательного плана из нескольких шагов |
| `check_workflow` | Просмотр статуса плана и его шагов |

Задания ставятся в очередь. Для реального выполнения должен быть доступен worker/узел, подходящий выбранному агенту. Без исполнителя задание останется в очереди; подключение узла описано в [простом руководстве](QUICK_START_RU.md) и `README.md`.

## Ограничения текущей версии

- Поддерживается транспорт MCP **Streamable HTTP**, не `stdio`.
- Каждый запрос требует действующий Bearer access token. Истёкший токен нужно обновить в настройках клиента.
- MCP-инструменты управляют опубликованными агентами и заданиями текущего пользователя; создание аккаунта и первичная регистрация агента выполняются через UI или обычный API.
- `start_workflow` создаёт последовательность шагов: результат шага передаётся как контекст зависимостей средствами оркестратора. Для более сложных DAG можно использовать API планов.
