# Подключение Agent Civilization через MCP

Agent Civilization предоставляет **MCP-сервер по HTTP**. Подключите его к совместимому MCP-клиенту (например, AI-ассистенту или автономному агенту), и тот сможет управлять вашими агентами через тот же сервер: создать черновик, добавить версию, запустить проверку в песочнице, опубликовать или архивировать агента, отправлять задания и запускать планы.

## Что нужно

1. Запущенный Agent Civilization: API доступен по адресу `http://localhost:8000`.
2. Учётная запись в Agent Civilization.
3. MCP-клиент, который поддерживает **Streamable HTTP** и пользовательские заголовки.
4. Долгоживущий API-ключ Agent Civilization. Создайте его в меню **Ключи API и MCP**; полный секрет показывается только один раз. Назовите его, например, «MCP на телефоне».

**Адрес MCP-сервера:** `http://localhost:8000/api/v1/mcp`

В удалённом окружении замените `localhost:8000` на адрес своего сервера и используйте HTTPS.

## Создать API-ключ через API

Проще всего создать ключ на странице **Ключи API и MCP** в веб-интерфейсе. Если удобнее через API, сначала войдите (`POST /api/v1/auth/login`), затем используйте текущий `access_token` один раз для создания ключа:

```bash
curl -X POST http://localhost:8000/api/v1/auth/api-keys \
  -H 'Authorization: Bearer ВАШ_ACCESS_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"name":"MCP client","expires_in_days":90}'
```

Скопируйте поле `api_key` из ответа в MCP-клиент. Ключ предназначен только для `POST /api/v1/mcp`: он использует права владельца внутри MCP, но не даёт доступа к остальным REST API-эндпоинтам. Его можно отозвать или создать заново в веб-интерфейсе; срок действия выбирается от 1 до 365 дней. Сервер хранит только хеш, поэтому посмотреть секрет позже нельзя.

## Пример настройки

В настройках MCP-клиента укажите URL сервера и HTTP-заголовок авторизации:

```json
{
  "mcpServers": {
    "agent-civilization": {
      "url": "http://localhost:8000/api/v1/mcp",
      "headers": {
        "Authorization": "Bearer ac_live_ВАШ_API_КЛЮЧ"
      }
    }
  }
}
```

Формат файла настройки зависит от MCP-клиента. Не отправляйте API-ключ в переписку и не коммитьте файл с настоящим ключом.

## Пример: создать, проверить и опубликовать агента

Попросите AI-клиента: «Создай агента echo с возможностью `text.echo`, добавь Python-версию, которая принимает `input.text`, возвращает `echo` и `length`; проверь на примере `hello`, и только если проверка успешна — опубликуй».

Ожидаемая последовательность MCP-вызовов:

1. `create_agent` — создаёт черновик и возвращает `agent_id`.
2. `create_agent_version` — сохраняет код, входную/выходную JSON-схемы и лимиты. Версия по умолчанию не публикуется.
3. `test_agent` — запускает Python-код в песочнице, проверяет схемы и возвращает итог `passed`/`failed`, список проверок и пример результата. Поддерживаются и черновики.
4. Если проверка успешна, `publish_agent` публикует агента. Если нет — AI может вызвать `create_agent_version` ещё раз с исправленным кодом и протестировать новую версию.

При обновлении уже опубликованного агента сначала вызовите `publish_agent` с `publish=false`. Это переводит агента в черновик и не позволяет новой непроверенной версии стать активной до повторной публикации.

Конфигурация точки входа (включая код и секреты) не возвращается в ответах MCP. Для изменения или удаления доступен только агент владельца; удаление опубликованных агентов запрещено — сначала снимите его с публикации, а при наличии истории заданий используйте архивирование.

## Инструменты MCP

| Группа | Инструменты |
|---|---|
| Каталог и возможности | `find_agents`, `list_capabilities` |
| Мои агенты | `list_my_agents`, `get_my_agent`, `create_agent`, `update_agent`, `replace_agent_capabilities` |
| Версии и публикация | `create_agent_version`, `list_agent_versions`, `test_agent`, `publish_agent`, `rollback_agent_version`, `suspend_agent`, `resume_agent`, `archive_agent`, `delete_draft_agent` |
| Задания | `run_agent`, `check_task`, `list_my_tasks`, `cancel_task` |
| Оркестрация | `start_workflow`, `check_workflow`, `list_my_workflows`, `cancel_workflow`, `retry_workflow_step` |

Задания ставятся в очередь. Для реального выполнения должен быть доступен worker/узел, подходящий выбранному агенту. Без исполнителя задание останется в очереди; подключение узла описано в [простом руководстве](QUICK_START_RU.md) и `README.md`.

## Ограничения

- Поддерживается транспорт MCP **Streamable HTTP**, не `stdio`.
- API-ключи ограничены MCP endpoint и не открывают обычные REST API-эндпоинты. Создавайте отдельный ключ для каждого клиента и отзывайте его при необходимости.
- MCP повторно использует проверки владельца, валидацию, бизнес-правила, аудит и песочницу платформы; инструменты не дают админских прав обычному аккаунту.
- `start_workflow` сейчас запускает последовательные шаги. Для сложных DAG используйте обычный API планов.
