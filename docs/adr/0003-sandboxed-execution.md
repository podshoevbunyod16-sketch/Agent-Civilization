# ADR-0003: Исполнение агентов только в песочнице

**Статус:** принято · **Дата:** 2026-11-05

## Контекст

Правило роадмапа №7: недоверенный код агентов нельзя запускать внутри
основного backend. При этом нужна возможность быстро проверить агента
разработчику и полноценно исполнять его на узлах.

## Решение

Два раннера за одним интерфейсом `SandboxRunner`:

1. `subprocess` — для разработки и тестов: отдельный процесс, `-I -S`,
   стерильный `env`, `RLIMIT_CPU/AS/NOFILE/NPROC`, wall-clock таймаут,
   ограничение вывода, временный рабочий каталог.
2. `docker` — production: `--network none` (по умолчанию), `--read-only`,
   `--cap-drop ALL`, `no-new-privileges`, `--user 65534`, лимиты cgroups.

Контракт агента языко-независим: вход `input.json`, выход `output.json`;
для Python дополнительно `run(payload) -> dict`.

## Обоснование

* Правило №7 соблюдается буквально: API-процесс не вызывает `exec` над кодом
  агента ни в каком режиме.
* Один интерфейс → тесты одинаковы для обоих раннеров.
* JSON-контракт позволяет позже добавить раннеры для Node.js, Go, WASM.

## Последствия

* (+) Компрометация агента ограничена процессом/контейнером.
* (+) Лимиты проверяются тестами (память, время, размер вывода, изоляция env).
* (−) `subprocess`-раннер не блокирует сеть на уровне ядра — задокументировано
  как ограничение dev-режима.
* (−) Docker-раннер требует наличия docker на узле; при его отсутствии
  узел возвращает понятную ошибку, а не падает.
