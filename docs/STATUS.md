## Осознанные ограничения (известные и задокументированные)

1. **Sandbox `subprocess` не блокирует сеть на уровне ядра.** Это dev/testing
   раннер. Для production предусмотрен `docker` (`--network none`, read-only,
   cap-drop). Ограничение зафиксировано в ADR-0003 и SECURITY.md.
2. **Anti-replay деградирует без Redis (fail-open).** Подпись и временное окно
   проверяются всегда; при недоступности Redis инцидент логируется. Выбор в
   пользу доступности, см. ADR-0002.
3. **Репутация пока базовая** — сглаженное отношение успешных задач к общим.
   Независимая проверка результатов, апелляции и разделение «заявлено/проверено»
   на уровне вычисления — этап 5.
4. **Уведомление узла о новой задаче — poll-модель** (по умолчанию 2 с).
   Push-уведомление через Pub/Sub запланировано на этап 3.
5. **Нет подтверждения email и восстановления пароля** — этап 1 в scope не
   включал, но для публичного запуска нужно.
6. **Экономики нет** — только поля-заготовки в схеме.
7. **A2A и MCP** — не реализованы; контракт `entrypoint_type` уже поддерживает
   `mcp`, а `http` покрывает A2A-стиль вызова.
8. **Нагрузочное тестирование, бэкапы, независимый аудит** — этап 9.

## Правила роадмапа: как соблюдены

| Правило | Как выполнено |
|---|---|
| 1–2. Не переходить дальше, не заменять функциональность заглушками | Этапы 0–2 закрыты тестами; UI и seed работают только через реальные API, MOCK DATA отсутствует |
| 3–4. Тесты фактически запущены, у каждой функции есть тесты | 101 тест, запуск в CI и локально, результат в отчёте |
| 5. Миграции проверены на чистой базе | `alembic upgrade head` на пустой БД в тестах; проверен downgrade/upgrade вручную |
| 6. Не допускать обхода авторизации и проверки владельца | Тесты security покрывают каждый изменяющий эндпоинт |
| 7. Недоверенный код не в backend | Исполнение только в `SandboxRunner` (subprocess/docker) вне процесса API |
| 8. Критические операции в аудите | `audit_log` + тесты на scoping и содержимое |
| 9. Совместимость API документируется | OpenAPI из кода, `docs/API.md`, коды ошибок перечислены |
| 10. Не усложнять микросервисами | Модульный монолит, ADR-0001 |
| 11–12. Независимость от провайдера и NovaMind | Агент — чёрный ящик за HTTP/JSON; NovaMind не является частью системы |
| 13. ADR | 5 ADR в `docs/adr/` |
| 14–15. Полный набор тестов перед завершением этапа, исправление ошибок | Найдено и исправлено 6 реальных дефектов (см. ниже) |

### Дефекты, найденные тестами и исправленные

1. Route ordering: `/nodes/{node_id}` перехватывал `/nodes/me` → выделен
   отдельный роутер с приоритетным подключением.
2. Anti-replay: `consume_once` возвращал `True` и при «Redis недоступен», и при
   успешном `SET NX` → введён сентинел `UNAVAILABLE`, replay теперь отсекается.
3. Отзыв сессий при replay откатывался вместе с ошибкой аутентификации →
   защитная мера фиксируется отдельной транзакцией.
4. Heartbeat: `sequence` от клиента вызывал конфликт уникальности → последовательность
   назначает сервер, клиентское значение сохраняется в `details`.
5. Устаревшие коллекции после изменения возможностей (identity map) → `populate_existing`.
6. `updated_at` с server-side `onupdate` вызывал `MissingGreenlet` при сериализации
   → вычисляется в Python.
7. Инъекция `ValueError` в тело ответа валидации ломала сериализацию → `jsonable_encoder`.
8. Удаление агента с версиями падало на `NOT NULL agent_versions.agent_id`
   (ORM обнулял FK вместо каскада) → `passive_deletes=True` + регресс-тест.
9. Удаление агента с историей заданий делало историю сиротой → возвращается
   `409 agent_has_tasks`, предлагается архивирование + тест.
