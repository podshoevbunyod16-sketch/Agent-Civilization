# Этап 10 — Production hardening & security

Ветка `arena/322d868a-agent-civilization` → `main`. Ничего не коммитилось в
`main`; история `main` не переписана.

Правило, по которому сделан этап: **реализовано ≠ проверено**. Ниже по
каждому пункту указано, что проверено автоматически, что реализовано, но
проверяется только в инфраструктуре, и что осознанно не сделано.

## Что в этом PR

| Этап | Содержание |
|---|---|
| A | Аудит по 17 направлениям; исправления: ротация секрета узла (CRITICAL), WS-тикет вместо токена в query, спуфинг IP через `X-Forwarded-For`, fail-closed anti-replay, SSRF-защита с DNS-rebinding, rate-limit с локальным резервом |
| B | Подтверждение email, сброс пароля (TTL, single-use, хеш в БД), TOTP 2FA для админов с одноразовыми кодами восстановления, отзыв сессий, блокировка перебора по аккаунту, аудит админ-действий |
| C | Secret management: AES-256-GCM (`cryptography`), кольцо ключей с версиями, ротация и отзыв, маскирование в логах, валидация конфигурации при старте |
| D | Распределённая надёжность: outbox (at-least-once, ADR 0013), `SKIP LOCKED`, fencing аренды, возврат застрявших отправок, retry с backoff, dead-letter |

| G | Метрики заданий (duration/execution/outcome), MCP-отказов, пула БД, живости воркеров; структурированные логи с корреляцией; предупреждения в `/ops/health` |
| H | Нагрузка и chaos с фактическими замерами, найденные дефекты исправлены и закрыты тестами |

| J | Production checklist, `.env.example` (все 69 настроек), security policy и порядок раскрытия уязвимостей, runbook бэкапа, отказ старта в небезопасной конфигурации |

## Доказательства

```
$ cd backend && pytest -p no:cacheprovider
529 passed, 3 warnings in 490.61s          # было 376 на этапе 9

$ ruff check app tests scripts
All checks passed!

$ bandit -r app -ll -ii                    # 0 HIGH
$ pip-audit                                # No known vulnerabilities found
$ alembic heads                            # a1f4c9d2e7b3 (head)

$ cd frontend && tsc --noEmit && npm run build
✓ built in 1.34s — 299.49 kB JS (gzip 89.94 kB)
```

Нагрузка и chaos (2 vCPU, локальный Postgres 16, fakeredis по TCP, 1 процесс
API, 120 запросов на профиль при конкурентности 10):

| Профиль | RPS | p50 / p95 / p99 | Ошибки |
|---|---|---|---|
| read (`GET /agents`) | 85.6 | 113 / 188 / 205 мс | 0 |
| mixed (80 % чтений + 20 % заданий) | 76.3 | 128 / 203 / 241 мс | 0 |
| auth (вход, PBKDF2 260k) | 21.5 | 459 / 583 / 702 мс | 0 |

Chaos: `redis-down` (0 ответов 5xx, подписи узлов fail-closed),
`redis-flap` (0 ответов 5xx), `db-pool-exhausted` (40 параллельных при пуле
10+20 → 40×200), `worker-killed` (аренда взята по HMAC, истекла через
10.1 с, возвращена в очередь, `requeued_tasks=1`).

## Дефекты, найденные при работе над этапом (и исправленные)

1. **Потеря денег при конкурентных переводах** — `_lock_accounts` без
   `populate_existing` отдавал из identity map старый баланс (lost update).
2. **Просроченные задания залипали в очереди навсегда** — дедлайн
   проверялся только при выдаче задания узлу.
3. **Просроченные задания «съедали» окно выдачи** — узел получал пустой
   список при живой очереди; найдено chaos-тестом.
4. **Восстановление бэкапа смешивало строки** — схема `restore_<unixtime>`
   без суффикса, два восстановления в одну секунду ломали сверку.
5. **bandit B103: мировые права в docker-sandbox** (`0o777`/`0o666`) —
   заменено на uid/gid хоста и права 0o750/0o640/0o660.
6. **`MetricsRegistry.observe_duration` падал с `KeyError`** при сбросе
   реестра — создаёт гистограмму вместо индексации.

## Чего в этом PR нет (и почему)

| Что | Статус | Причина |
|---|---|---|
| Exactly-once доставка событий | не заявляется | outbox at-least-once, ADR 0013; подписчики идемпотентны по `event_id` |
| Внешний Secret Manager (Vault/KMS) | ❌ | интерфейс `SecretProvider` готов, сервис — задача инфраструктуры |
| PITR/WAL-архив | ⚙️ | требование к кластеру Postgres, не к приложению (runbook §5) |
| TLS-терминация, WAF | ⚙️ | зона балансировщика; HSTS приложение выставляет в production |
| Доставка алертов (Alertmanager/PagerDuty) | ❌ | метрики, пороги и предупреждения есть, маршрутизация — на платформе |
| Production-подобный стенд нагрузки | ❌ | нет балансировщика, реального Redis и внешнего драйвера: измерено то, что измерено |
| Независимый аудит/пентест | ❌ | внешняя задача, этап её не закрывает |

Полный список со статусами ✅/⚙️/❌ — `docs/PRODUCTION_CHECKLIST.md`.
Результаты замеров и их ограничения — `docs/runbooks/load-and-chaos.md`.
Политика безопасности и сроки реакции на уязвимости — `docs/SECURITY.md`.
